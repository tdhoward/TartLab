Protected qualification run 35935734637 rebuilt the candidate twice with
byte-identical output, passed 390 host tests, and authenticated all 32
release subjects against the source tag and protected signer policy. The
candidate is a platform-path release: it adds the non-Pro T-Display-S3
BOARD_CONFIG and RGB driver, changes shared display/input/runtime code,
changes the device IDE and browser bundle, and updates host build inputs.
The signed report therefore requests fresh adult provisioning, hardware,
OTA, recovery and release-feed isolation for all three included boards.

host-process interruption/resume campaign, display/button/browser/resource
checks, corrupted-package rejection, same-version OTA, a physical download
power cut, two recovery-install power cuts, offline resume and recovery-page
checks. It has no touch controller; physical design, board configuration,
runtime capability and a touch-only example's clear fallback establish that
absence. The complete observations and limitations are in
modern-v0.16.1-nonpro-physical-transcript.txt.

The existing LilyGO Pro PCB v1.1 and Elecrow DLE06235B fixtures were
upgraded from installed modern-v0.16.0 using that version's updater with
authenticated v0.16.1 assets staged over USB. Both kept old committed
versions through pending_health and reached v0.16.1 only on healthy boot.
Both had matching protected-state digests before/after normal OTA. Tim
performed fresh power-cycle, screen, touch/navigation and browser IDE
checks. Machine probes covered display ownership, Wi-Fi scan concurrency
and initialization cycles. Both rejected a corrupted archive before active
installation, survived a physical recovery-install power cut, displayed
the recovery Wi-Fi controls and redacted diagnostics, resumed staged
packages offline and reached healthy v0.16.1 with no marker. Both were
clean provisioned with an intentional host-process termination during final
boot-file activation, resumed to healthy boot and matched 81 of 81 managed
files in the signed prepared image. Exact outcomes and limitations are in
the Pro and Elecrow v0.16.1 physical transcripts.

The existing boards' firmware binary hashes are byte-identical to those
in the qualified modern-v0.16.0 baseline. The updater and recovery
