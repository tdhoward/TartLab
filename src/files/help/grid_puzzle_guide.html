Grid puzzle: rooms and editable Python

This project targets the modern TartLab platform (lvgl-modern) only.

First playable room. Move the white P, push the O boulder into blue water to make a crossing, collect the required K key, and reach E. The exit turns green when unlocked. The * diamond is optional. The HUD shows keys (K), score (S), remaining bonus (B), and play status. This is Phase 2; dirt, false walls, teleportation, messages, hazards, original sprite artwork, and the teaching campaign are upcoming.

Hold a direction to repeat; release to stop. Reset restarts the current room, Pause/Play freezes/resumes it, and Back returns to the UI. After completion, Next advances if another room is loaded; Done means the pack is finished. Reset also works when paused or after completion. Release all controls before pressing again after launch, restart, pause/resume, or completion. Tap a cell to inspect it in the console. The built-in First Crossing room introduces the supported rules; push toward the water from its left, then explore the other side for the key.

Make independent copies

  1. Open Grid puzzle: First Crossing in Help. Save as my_puzzle.py. Help files can be saved without first changing them.
  2. Run the saved Python copy. It initially uses the bundled rooms through LEVEL_FILE = "/files/help/grid_puzzle_levels.json".
  3. Open Grid puzzle: room data in Help. Save as my_rooms.json. JSON opens in the text editor; Save is available, while Run and Set as App apply only to Python files.
  4. Change your Python copy to LEVEL_FILE = "/files/user/my_rooms.json", save, and run again.

Renaming Python does not change its data paths. The example prints the selected path and any JSON error in the console; an invalid custom file never falls back to the bundled rooms. Python names and folder names use letters, digits, and underscores. Both Python and JSON remain ordinary editable files.

Room format

The root is an object with "version": 1 and a nonempty "levels" array. Each room requires a nonempty name and map. A map has exactly 12 strings, each containing 16 two-character tokens separated by spaces. Extra whitespace is allowed; token case matters. Coordinates start at column 0, row 0 in the upper left. Every room has exactly one player and one exit. Outer walls are optional; outside the room is blocked.

TokensMeaning
.. P. E.Floor, player, exit
#0–#9Wall art variants
K. D. O.Required key, optional diamond, boulder
W0–W8Water; W9 is invalid
d0–d9Dirt art variants
F0–F9False wall matching the numbered wall
S.Stationary horizontal snake
RN RE RS RWSpear emitter heading north, east, south, west
Xn Xe Xs XwSpider heading north, east, south, west; follows left
XN XE XS XWSame headings; follows right
T0–T9Paired pads; each used label occurs exactly twice in a room

For example, Xe and XE both start facing east, but follow different walls. XL, XR, T., lowercase x, and omitted headings are invalid. Pads are symmetric; neither twin is a designated source. Pad links and spider settings come entirely from the map. Each token defines its own terrain and occupancy, so layers cannot be stacked by adding metadata.

Water variants form a 3×3 atlas: W0/W1/W2 are the top row, W3/W4/W5 the middle, and W6/W7/W8 the bottom. W4 is all water; the others show banks. All nine block a full logical cell. Art variants do not change collision rules.

Optional room fields:

  • bonusStart: nonnegative integer, default 500.
  • timers: object with optional player_ms (110), spider_ms (150), and projectile_ms (40). Every interval must be an integer at least 10 ms. Nonmultiples of 10 are serviced on the next simulation boundary, with deadlines advanced from the previous due time.
  • actors: at most 192 annotations such as {"x": 12, "y": 7, "step_ms": 40}. Only an existing spear emitter can be annotated. A location may occur once; headings cannot be overridden.
  • messages: at most 192 records such as {"loc_x": 3, "loc_y": 2, "text": "Look at the crossing."}. One message per cell; locations must be player-enterable terrain without a stationary enemy. Dirt, false walls, and pads may carry messages. Messages pause gameplay and trigger once per attempt, including at the player start.
  • rules: explosion_destructible is an array containing any nonduplicated subset of "BOULDER" and "DIRT" (both by default). explosion_diamonds and explosion_hurts_player are booleans, both defaulting to true.

Use double quotes, lowercase true/false, and no comments or trailing commas in JSON. Unknown fields, including teleporters, are errors. Booleans are never accepted as numbers. There is no imposed pack byte/room limit yet; device heap measurements will determine whether one is needed. Structural validation does not prove a solution.

Playable rules and upcoming mechanics

A move is one cardinal step. A failed attempt consumes its movement interval. Pushing moves one boulder atomically; chains, pulling, and pushing into actors, dirt, collectibles, exits, or pads are blocked. Water consumes a pushed boulder and becomes floor. All keys are required; zero-key rooms start with an active exit. A diamond scores 100, and the bonus falls by one per second of unpaused simulation, stopping at zero. Room score and the remaining bonus are banked only on completion. Restarting a completed room rolls back its award; earlier completed rooms remain banked.

A fresh press moves on the next eligible 10 ms simulation tick. Held movement attempts are 110 ms apart by default, including failed pushes. Changing direction does not reset this cooldown. After waiting past a deadline, the next press starts a fresh interval. Most recently pressed direction wins; releasing it restores another held direction if there is one. Touch is processed before named button events in a poll, so a simultaneous button press wins. New input takes effect after the elapsed simulation batch, avoiding movement before the press was observed. Rendering uses a fixed 50 ms period; this is a proposed device setting, not a measured frame-rate guarantee.

The loader validates every token in the table, but starting play currently rejects rooms with dirt, false walls, pads, messages, or enemies with a clear Phase 3/4 diagnostic. Those mechanics have not been implemented yet. Their planned rules follow: dirt and false walls clear when the player enters.

Player and spiders teleport once per entry, preserving direction and timers. A blocked twin leaves the actor on the entered pad until it leaves and reenters. False walls match wall pixels; pads match floor in normal play. Snakes attack horizontally. Walls, dirt, collectibles, boulders, locked exits, actors, and spears provide cover. Spiders choose left/forward/right/backward or its right-following mirror. Due spiders move in source-map order. A trapped set is determined before removing any member.

Explosions cover the center plus its four cardinal neighbors, clipped at room edges. They cannot destroy keys, walls, false walls, exits, pads, other actors, or spears. Drops occupy only newly cleared empty floor or an empty blast center. Spear traps detect along their map heading, then grow one cell per deadline; stopped shafts are solid and harmless and never rearm. Hazards continue while the player is idle; death takes precedence over reaching an exit.

Find and change the Python

The source has eight numbered sections: settings, symbols, loading/state, player interactions, hazards, simulation order, drawing, and input/main. Sections 4 and 6 now contain movement and simulation; Section 5 reserves hazards. The maintained file is the same file you copy: it is not generated from hidden engine modules.

Follow a move through Controls.poll, run, Session.advance, step, move_player, collect_player_object, and draw_game. The collision checks are can_player_enter and accepts_boulder.

Change DIAMOND_SCORE to 37, save and rerun, and collect the diamond to see the score change. Or edit the addition in collect_player_object itself: your copy executes that actual implementation. Change PLAYER_MS to 220 for slower movement. Defaults apply only when the room or supported actor omits its override; the supplied room omits timers. Try changing the room name or a wall token independently in JSON. Later lessons add snake cover and spider turns.

Restart, rerun, and restore

  • Restart Level (the Reset control) reconstructs in-memory state using the currently loaded definition. It does not undo code edits or reload saved files.
  • Save and rerun executes the saved Python source again and reloads the selected JSON. The IDE Run action reads the file and executes it; it does not import a cached copy of your engine. Selected-app startup imports the saved module after a device reset. Reset before relaunching a selected app after editing it.
  • Restore the example: close your copy's tab, reopen the original Help entry, and save a new user copy. Restore Python and JSON independently; keep experiments under distinct names.

Help originals are update-managed. Download copies to preserve a particular version. Neither restart nor game launch writes Python or JSON. Syntax and runtime errors remain visible in the console. If a loop prevents the IDE from responding, interrupt from the device console with Ctrl-C, or reset the device and use its existing IDE/launcher startup route to avoid autorunning the broken app. Console Reset clears pseudo-REPL globals when the IDE is responsive; it is not a way to interrupt a blocked interpreter. Fix or replace the saved copy, then save and rerun. Reopening Help restores the currently installed baseline.

Layout expectations

The game reserves the whole 256×192 room, a HUD, and 32-pixel touch targets. It tries both orientations and chooses the largest integer tile scale, favoring a side panel. Smaller incompatible screens produce a clear error. Button-only input requires the names up, right, down, left, restart, pause, and back; two-button navigation is outside this version. The console reports the chosen rotation, scale, and level path. Physical readability, control comfort, heap use, and frame rate still require device observations.
